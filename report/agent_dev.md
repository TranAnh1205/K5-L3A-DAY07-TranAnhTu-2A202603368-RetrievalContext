# Day 7 real-model dev runs and improvement trials

The agent ran on all 17 fixed **dev** cases (15 answerable and 2 no-evidence) with `gpt-5.4-mini` via OpenAI API. All runs used the same 484 Day 6 A chunks from Qdrant/TF-IDF export, the same question wording and user-supplied filters, top-3 results per search, at most 2 searches, and a 4,000-character context budget. Context packing keeps complete chunks with ID, source and physical PDF page and deduplicates IDs. The benchmark SHA-256 is `3bb60bee86dc22e974cf074b9bb9d1abbc83f1f2ce28dbc38d089b5546be28ab`; exported chunk JSON SHA-256 is `4a2d84fcda9c3e8c36ff804620f03f0a40c7f9a6b16b0b21700a3145f09b51f1`. No benchmark gold or expected behavior entered model requests. These dev runs and configuration selection happened before any Day 7 test case was run; the later held-out evaluation is documented in [`agent_test.md`](agent_test.md).

The three configurations are baseline dense Qdrant, improvement trial 1 hybrid RRF (20 dense and 20 TF-IDF candidates fused by rank), and improvement trial 2 the same hybrid plus one optional repair turn when a generated citation ID is invalid. The repair turn receives only exact IDs present in the current context; it does not add evidence. The second trial leaves retrieval ranking unchanged.

## Error analysis and before/after

1. **`d09`, wrong population condition.** Dense cited page 40's 16.2% to 10.6% for households with *only* farming income, while the question asks households with farming as *any* income source (66% to 46%). Hypothesis: lexical overlap in hybrid would bring the more precise page 36 evidence into context. Hybrid answered 66% to 46% with page 36; the repair trial regressed to the wrong page 40 answer. This improvement is not stable in the three single runs.
2. **`d11`, mistyped citation ID.** The first hybrid run retrieved page 42's correct evidence but generated a chunk ID with one wrong character. The starter correctly abstained. Hypothesis: one repair turn with valid context IDs could recover such answers without inventing a source. In the repair trial, `d11` answered correctly on the first attempt, so that run does **not** demonstrate a successful repair. The only actual repair attempt was on no-evidence `d17`; it still abstained. The repair trial cost more and lowered answer quality in this run.
3. **`d13`, insufficient citation.** Dense cited only a figure note about official urban/rural classification. Hybrid retrieved page 58, which explicitly contrasts the official 39% share with a potentially larger urbanized population under alternative measurement. Hybrid's answer and citation were adequate. The repair trial used chart labels without the needed explanatory passage and was marked unsupported.

For `d12`, all three agents gave the correct 30%-to-almost-40% answer using a Part 2 excerpt on physical PDF page 65. The frozen gold span is on page 56, so strict automatic gold matching marks this as a miss. The reviewed context and answer labels accept page 65 as an equivalent source; the exact alternative is recorded in [`gold_alternatives_reviewed.json`](agent_dev/gold_alternatives_reviewed.json). The benchmark JSON and original-query retrieval scores remain unchanged.

## Selection before test

The predeclared rule in `data/BENCHMARK_PROTOCOL.md` selects the highest dev Evidence Hit@3, then Context Evidence Rate, then lower latency. All three have 12/15 on the original-query Evidence Hit@3. The **selected configuration is Hybrid RRF** because its final context has 13/15 adequate evidence versus 12/15 for dense and 11/15 for hybrid with repair. Its exact parameters and corpus/benchmark hashes are frozen in [`selected_config.json`](agent_dev/selected_config.json) before any test run. It does not improve grounded-answer mean over dense and has one false abstention; those limitations remain in the report. Model sampling variation means these single-run differences are not proof of a stable quality gain.

The [cases](agent_dev/cases.json) and per-configuration directories under `report/agent_dev/` contain the full question-level traces, aggregate run summaries, completed labels and metrics generated by `starter/agent_metrics.py`. Reproduce the three dev runs using `src/run_agent_dev.py` with the corresponding `--method` and `--citation-retries` values; see `src/README.md`. The context budget is measured in Python string characters, including citation header/source text. Candidate count for hybrid is 20 per retriever before RRF; dense and TF-IDF single methods request top-3. Query, results, final context, citation, usage, timing and error status are stored for each case.

## Source-PDF audit

All 15 answerable dev gold spans were found in the stated physical PDF pages. The cited chunks and final answers were read for all three configurations. Pages 36 and 40 were visually checked to distinguish *any* farming income (66% to 46%) from *only* farming income (16.2% to 10.6%). Pages 56 and 65 were visually checked for the equivalent `d12` evidence; page 58 was checked for the official-versus-alternative urbanization claim. Pages 20 and 42 were checked for the full two-part `d03` answer and the `d11` no-COVID comparison. For the no-evidence cases, the 67-page indexed corpus was searched, and PDF pages 69 and 75 were visually checked: the computer figure gives grid-level patterns but no HCMC-wide percentage, and the 2025 housing value is a target rather than an observed outcome. No label changed from the initial proposed review after this audit. No Day 7 test data was used.
